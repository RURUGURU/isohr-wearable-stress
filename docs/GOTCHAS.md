# Gotchas

Things that will cost you an afternoon if nobody tells you.

## Protocol parameters are process-global

`utils_analysis.WIN` and `STEP` are module-level globals read from
`analysis_config.ini` at import. The `sensitivity` CLI command **mutates them**:

```python
isohr.WIN = 300.0
isohr.STEP = 150.0
```

So two sensitivity protocols must never share a process, and any code that
caches window-derived state across a change of `WIN` is wrong.
`analysis_hrv.run_hrv_window_sensitivity` restores the originals in a `finally`
block for exactly this reason — copy that pattern.

## `plot_figures.py` fails on purpose

`_require_rows` raises if a parsed log has a different number of rows than
expected. That is not a bug: the figures are generated by parsing the result
logs rather than by copying numbers, so a changed log format must stop the build
instead of silently producing a figure that disagrees with the table.

## `pytest.ini` turns warnings into errors

`filterwarnings = error` means an unrelated upstream `DeprecationWarning` will
turn the suite red. If tests fail immediately after a dependency bump, read the
warning before suspecting your change.

## The strict quality surface is deliberately partial

`pyrightconfig.json` includes 16 files and `run_quality.sh` lints the same set.
`utils_analysis.py`, `analysis_crosscorpus.py` and `analysis_statistics.py` are
**excluded on purpose**: they are numerically frozen against published results,
and a large type/format refactor there risks changing a paper number for no
scientific gain. They are protected by regression tests instead — in particular
the Nurse cohort assertion `9226|7347|1879|15` in `test_nurse.py`.

If you edit them, re-run `scripts/run_crosscorpus.sh` and diff the log against
the committed one before doing anything else.

## `FEATS` order is load-bearing

`utils_analysis.FEATS` defines `IDX`, `NONHR` and every column index used by the
models and by the iso-HR decomposition. Reordering or inserting into it changes
results everywhere with no error. Activity features live in a separate
`ACC_FEATS` list precisely so they could be added without touching `FEATS`.

## The HRV sensitivity used to write a figure

`analysis_hrv.py` previously wrote `F7_hrv_window_sensitivity.png`, which
duplicated every value in the HRV table. Reviewer 1 objected to the redundancy,
the figure was removed from the manuscript, and the `savefig` call was deleted.
Do not reintroduce it; the table is the sole presentation of that result.

## Figure file names are not figure numbers

`F8_adaptation.png` renders as Figure 3. See the mapping table in
[ARCHITECTURE.md](ARCHITECTURE.md#4-figures).

## Nurse timestamps depend on the host timezone

Nurse survey times are wall-clock and must be interpreted in `Asia/Seoul`.
`utils_time.nurse_survey_epoch` handles this; the integration test pins the
result so a machine in another timezone cannot silently rebuild a different
cohort.

## The single-SCR score can legitimately be below chance

Its direction is fixed a priori and is never flipped using test labels. A
below-chance AUROC is a real result about the corpus, not a sign error — see
the Nurse within-corpus row.

## Accelerometer loading must never drop a window

`build_sp` wraps ACC loading in its own `try` and falls back to an empty array,
so a missing or malformed ACC file yields NaN activity features rather than a
smaller cohort. Preserve that property: the cohort counts are asserted in tests
and quoted throughout the manuscript.

## Peer-review correspondence is not in the public repository

`.gitignore` excludes `reviews/`, `response_to_reviewers.md` and
`major_revision_matrix.md`. They exist in the working tree but are withheld until
the journal and the reviewers agree to publication. Do not `git add -f` them.
